What Improved

- Login/signup:
  - Duplicate email and auth errors stay inline and accessible.
  - Error banners now use aria-live .
  - Redirect-after-login coverage was expanded.
- Onboarding/store creation:
  - Draft restoration remains refresh-safe and now shares cleanup with logout/session recovery.
  - 403 and ambiguous create-store failures route back through bootstrap-safe recovery instead of leaving the form in a bad state.
  - Missing bootstrap/onboarding snapshots render recovery UI instead of null .
- Provisioning:
  - Completed provisioning performs an explicit final bootstrap handoff.
  - Dashboard CTA is only shown when the active store is actually ready.
  - Malformed provisioning payload fallback is covered in E2E.
- Multi-tab sync:
  - Guest tabs now refresh bootstrap reliably after login in another tab.
  - Logout and active-store changes stay browser-native and bootstrap-driven.

  - The UI reliably stays in a recoverable onboarding state with manual actions, but not every reconnect path auto-unlocks immediately.

  - I kept this work scoped to the auth/onboarding/dashboard flow and did not refactor unrelated surfaces.

Manual QA Checklist

- Register with a new email and verify the app lands on onboarding verification UI.
- Register with an existing email and confirm inline duplicate-email rendering.
- Visit a protected route as guest, log in, and confirm redirect returns to the original route.
- Log in on one tab while another tab is on /login and confirm bootstrap sync redirects the guest tab.
- Create a first store, refresh during provisioning, and confirm the provisioning screen restores.
- Force provisioning failure/timeout and confirm recovery UI stays in onboarding.
- Switch stores and confirm sidebar permissions update atomically with the route.
- Log out in one tab and confirm the second tab loses protected access.
- Expire a session during a protected dashboard page reload and confirm redirect lands on login with the expired marker.
